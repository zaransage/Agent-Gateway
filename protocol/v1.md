# Agent Protocol v1

A compact structured format for inter-agent communication.
Designed to minimise token cost while remaining human-readable and machine-parseable.

---

## Motivation

Natural language prose between agents is expensive: 400–800 tokens to convey what a structured
header expresses in 40–60. This protocol defines a minimal envelope that any LLM can produce
and parse without prompt engineering.

The format is intentionally simple enough to fit inside a URL query parameter.

---

## Envelope Format

```
AGENT/<verb> v1
<key>: <value>
<key>: <value>
---
<optional prose body — agents MAY skip unless detail is needed>
```

The header block ends at the first `---` line. Everything after is the body.
An envelope with no `---` has no body.

---

## Verbs

| Verb | Direction | Purpose |
|---|---|---|
| `TASK:submit` | Client → Gateway | Submit work to the agent fleet |
| `TASK:status` | Client → Gateway | Poll status of a submitted task |
| `TASK:result` | Gateway → Client | Full result of a completed task |
| `TASK:ack` | Gateway → Client | Acknowledgement of submission |
| `AGENT:ping` | Client → Gateway | Health check |
| `AGENT:pong` | Gateway → Client | Health check response |

---

## TASK:submit

**Required fields:**

| Key | Type | Description |
|---|---|---|
| `title` | string | Short task title (< 80 chars) |
| `desc` | string | What the agent should do |

**Optional fields:**

| Key | Type | Description |
|---|---|---|
| `pri` | `high` \| `normal` \| `low` | Priority (default: `normal`) |
| `tags` | comma-separated strings | Routing hints (`code`, `backend`, `gdscript`, `art`, etc.) |
| `files` | comma-separated paths | Files the agent should focus on |
| `accept` | comma-separated strings | Expected output variants (e.g. `table,json,csv`) |
| `design_ref` | URL | Link to full design document (fetched by gateway) |
| `reply_to` | agent ID or URL | Where to send `TASK:result` when done |

**Example:**

```
AGENT/TASK:submit v1
title: Add --format flag to board subcommand
desc: Extend cli_adaptor.py board command to support --format table|json|csv
pri: high
tags: code,backend
files: domain/ipo_scanner/core/adaptors/cli_adaptor.py
accept: table,json,csv
```

**Response:** `TASK:ack`

---

## TASK:ack

Returned immediately on successful submission.

```
AGENT/TASK:ack v1
id: 012
status: queued
poll: /task/status?id=012
```

---

## TASK:status

```
AGENT/TASK:status v1
id: 012
```

**Response fields:**

| Key | Value |
|---|---|
| `id` | task ID |
| `status` | `queued` \| `active` \| `done` \| `failed` |
| `agent` | claiming agent ID (if active) |
| `notes` | progress notes from heartbeat (if active) |
| `poll` | suggested next poll endpoint |

---

## TASK:result

Returned when `status` is `done`.

```
AGENT/TASK:result v1
id: 012
status: done
agent: claude-abc123
pr: https://github.com/zaransage/IPO-Tracker/pull/42
---
Board command now accepts --format table|json|csv.
Default remains table for backwards compatibility.
```

---

## AGENT:ping / AGENT:pong

```
AGENT/AGENT:ping v1
from: gpt-4o-browser
```

```
AGENT/AGENT:pong v1
gateway: agent-gateway/1.0
queue_depth: 3
agents_active: 2
```

## Encoding for GET requests

The envelope is URL-encoded and passed as the `msg` query parameter:

```
GET /agent?msg=AGENT%2FTASK%3Asubmit+v1%0Atitle%3A+...
```

Helper: the gateway accepts `msg` as the raw envelope string. Newlines may be `\n` or `%0A`.

---

## Token budget

| Envelope | Approx tokens |
|---|---|
| TASK:submit (minimal) | ~35 |
| TASK:submit (full fields) | ~60 |
| TASK:ack | ~20 |
| TASK:result (no body) | ~30 |
| English prose equivalent | 400–800 |

---

## Versioning

Breaking changes increment the version (`v2`). The version is in the first line of every envelope.
Gateways MUST reject envelopes with unsupported versions with HTTP 400 and a `TASK:error` response.

---

## Extension

New verbs are additive. Unrecognised keys within a known verb are ignored (forward compatibility).
Unrecognised verbs return HTTP 400.
